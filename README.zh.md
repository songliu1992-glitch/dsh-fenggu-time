# dsh-fenggu-time

一个 DeepSeek Harness 插件：在窗口标题栏放一个 22px 的徽章，显示 DeepSeek API **当前处于哪个计费时段**。

```
● 梁文峰时间    黄色 #ffd60a    高峰时段    —— 按全价计费
● 梁文谷时间    绿色 #55ff55    空闲时段    —— 价格为高峰时段的一半
```

两个文案取自「梁文峰」的谐音：峰（高峰）与谷（空闲）。**绿色代表你的 API 调用正按空闲时段价格计费，价格只有高峰时段的一半**——措辞与 DeepSeek 官方价格文档一致。

徽章只做被动显示：固定在标题栏那一行、与窗口右侧的最小化/最大化/关闭垂直居中、点击穿透，并且切到任何页面（会话、插件、设置）位置都不变。不弹窗、不轮询。

## 时段规则

直接引自[模型 & 价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing)：

> 空闲时段价格为高峰时段价格的一半。北京时间周一至周五（不含中国法定节假日）9:00 - 12:00、14:00 - 18:00 为高峰时段；其余时段，包括周末及中国法定节假日全天均为空闲时段。

官方英文页把同一规则表述为 UTC：高峰为周一至周五 `01:00–04:00` 与 `06:00–10:00`（UTC），排除中国法定节假日。这两个窗口换成北京时间正好是 9:00–12:00 与 14:00–18:00，且都不跨午夜，所以星期几不会有歧义。

| | 条件 | 徽章 |
|---|---|---|
| 高峰时段 | 周一至周五、非中国法定节假日、北京时间 09:00–12:00 / 14:00–18:00 | 梁文峰时间，黄色 |
| 空闲时段 | 其余所有时间，含周末与中国法定节假日全天 | 梁文谷时间，绿色 |

中国法定节假日对全球所有账号都生效，所以境外用户的空闲时段与国内一致，只是**本地钟点不同**：

| 当地时区 | 高峰时段（当地） |
|---|---|
| 北京 UTC+8 | 09:00–12:00、14:00–18:00 |
| 东京 UTC+9 | 10:00–13:00、15:00–19:00 |
| 悉尼 UTC+11 | 12:00–15:00、17:00–21:00 |
| 柏林、巴黎 UTC+1 | 02:00–05:00、07:00–11:00 |
| 伦敦 UTC+0 | 01:00–04:00、06:00–10:00 |
| 纽约 UTC-5 | 20:00–23:00（前一天）、01:00–05:00 |
| 洛杉矶 UTC-8 | 17:00–20:00、22:00–02:00 |

边界左闭右开：09:00 与 14:00 算高峰，12:00 与 18:00 算空闲。两条必须说清的推论：

- **调休上班的周末算空闲。** 国务院调休把某个周六变成工作日，但按上面的规则它仍是周末，官方计费时段同样是按周一至周五写的。
- **没有节假日数据的年份按“无假期”处理**：工作日的高峰时段照常算高峰。

## 安装

```sh
dsh plugin add dsh-fenggu-time
```

或在客户端里：**插件 → 添加插件**，填 `dsh-fenggu-time`，安装源选官方 npm 源，装完重启 DSH。

## 节假日数据与每年自动检查

中国每年 11 月前后公布下一年的放假安排，写死的表一定会过期。**这个插件不需要你按任何按钮**：它每年 **12 月 31 日北京时间 12:00** 自动检查一次，第一次运行是 **2027-12-31**——2026 与 2027 的安排已经内置，2028 才是第一个没人知道结果的年份。

```sh
~/.dsh/plugin-state/fenggu-time-holidays.json   # Windows: %USERPROFILE%\.dsh\plugin-state\...
```

行为说明：

- 从已发布的 npm 包（jsDelivr）取最新表，只有版本更新时才保留，并写入 `node_modules` 之外的目录，重装插件也不会丢。
- 每次检查结束后自动排下一次（下一年 12 月 31 日 12:00），这条链不需要任何人维护。
- 元旦那天机器关着也不会漏：下一次启动后不久会补跑一次（但不早于上面那个首次时间）。
- 删掉上面那个文件即回退到内置表。
- 一年只发一次网络请求，且只在那一个时刻；其余时间不联网。

内置日期逐日抄自国务院办公厅通知：

- 2026 年 — 国办发明电〔2025〕7号 — <https://www.gov.cn/zhengce/zhengceku/202511/content_7047091.htm>
- 2027 年 — 国办发明电〔2026〕10号 — <https://www.gov.cn/zhengce/content/202611/content_7085101.htm>

**要知道的限制**：能更新的只有节假日表。每天那两个高峰窗口是代码里的常量——如果官方改了时段本身（改过：旧的北京时间 00:30–08:30 错峰优惠已于 2025-09-06 取消），必须发新版才能跟上。

## 运行时开销

一个徽章，一个闹钟。文案只可能在五个时刻变化：北京时间 00:00、09:00、12:00、14:00、18:00。插件据此算出下一次翻转的时刻，`setTimeout` 睡到那一刻再重排，一天大约醒五次，中间零开销。窗口获得焦点、页面重新可见时会重新对表并重排闹钟，所以系统休眠或渲染卡顿不会让文案停在旧状态。

## 兼容性

实测于 DSH `0.2.2-rc.3`（桌面端，Windows）。包**故意不声明** `engines.dsh`：DSH 发的是 rc 版本，而 semver 默认把预发布版本排除在普通 range 之外；一个不包含当前 rc 的 range 会让兼容性预检把整行静默禁用——表现是徽章消失，而不是报错。

徽章用的是内部客户端槽位（`shell.overlay`、`settings.general.item`）。它们不是兼容承诺：未来的 DSH 若改名，徽章与设置行会消失，插件按“失败即隐身”处理，不会让页面崩。

## 开发

纯 JavaScript，没有构建步骤：`lib/client.js` 就是客户端加载的浏览器产物（`window.__ModuleLoader__.load({ id, factory })`），`lib/index.js` 是 host 半（ESM，只用 node 内置模块）。

```sh
npm test    # 时段判定、闹钟调度、节假日文档校验、两条路由
```

测试用打桩的模块加载器加载实际发布的 bundle，并用假的 `webServer` 驱动 host 路由，验证的是会发布出去的那份文件，而不是副本。
